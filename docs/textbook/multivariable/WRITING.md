# 多元函数微分学：本轮写作约定

本轮重写概念文章、题型导读、逐方法文章，先完成适合人阅读的 Markdown。文章不按程序字段编写；不改网站代码或内容 JSON。上一轮 63 篇文章已删除，历史版本保留在 Git。

## 文章怎么写

读者已学一元微积分及基本向量运算。本章只定义新概念；先修概念至多一句提醒，不复述一元极限、中值定理、向量运算等章节。

概念文章按实际引入顺序组织。定义、结论及必要前提放在一起；主要数学表达用独立块公式，多个条件用 aligned、cases 或分行。正文解释一个关键点便换段，不把公式藏在长句中。不机械重复“直觉、符号、适用条件、步骤、易错点”等固定栏目。

题型是“要求求什么或证明什么”；方法是可单独选择执行的动作。例如“求二重极限”是题型，“连续性代入”“夹逼估计”“极坐标一致估计”“不同路径反证”是不同工具。

每篇方法文章围绕一种工具，把选用时机、条件、核心操作和 1—2 个完整演算自然串起来。尽量一个公式完成一个推理步骤。例题少而足，必要时附反例说明误用。

真题保留年份、数学一、题号与来源链接，只写原创摘要和推导。没有核对的表达式不猜；没有合适真题时使用明确标注的自编例题，并标明真题关联尚未核对。来源核验、题面整理、方法关联分别记录，不能把旧大类关联直接转给细分工具。

## 串行交接

1. 概念作者只写 concepts.md，另写必要的交接说明。
2. 概念完成后，题型作者写 problem-types/ 及 questions/，提出细分工具清单。
3. 题型完成后，方法作者按清单写 methods/；确需调整粒度可说明理由。
4. 主 agent 核对数学、示例、链接和排版，整理总目录与验收记录。

子 agent 的文件访问限本章 Markdown 与主 agent 提供的来源资料；禁止阅读或修改 src、scripts、tests、content、package 文件，也不运行项目代码。主 agent 已完成仓库规则与状态检查。

范围仍为“多元函数微分学”试做章。用户提供的参考文章是表达与粒度范例，不将其中未附原始来源的课纲版本说明自动认作已核验课纲。
